### 1. Архитектура программного комплекса
Программный комплекс спроектирован по принципам предметно-ориентированного проектирования (**Domain-Driven Design**) и чистой архитектуры (**Clean Architecture**), обеспечивая высокую отказоустойчивость и масштабируемость:

```
[Потоковые источники банка] (ДБО, Картридеры, Платёжные шлюзы Kaspi/Halyk)
                 │
                 ▼
     [Redis Streams / Event Hub] ──► [Ingestion Service (Python)]
                                               │
                                               ▼
                                   [Redis Feature Store (Hot Layer)]
                                               │
   ┌───────────────────────────────────────────┴──────────────────────────────────────────┐
   │                                                                                      │
   ▼                                                                                      ▼
[Core Backend (.NET 8 WebApi)] ◄────── gRPC Protocol Buffers ──────► [ML Inference Engine (PyTorch)]
   │ (CQRS, MediatR, EF Core)                                          │ Dual-Tower Cross-Attention Net
   │                                                                    │ Google OR-Tools MILP Solver
   ▼                                                                    ▼
[Client Web Portal & Dashboard (Next.js 15)]                 [Explainable AI (XAI) Matrix]
```

#### Ключевые компоненты:
1. **Core Backend (`RiskTwin.WebApi`, .NET 8):**
   * Чистая архитектура: разделение слоев `Domain`, `Application`, `Infrastructure`, `WebApi`.
   * Высокопроизводительные gRPC-клиенты со строгой типизацией на Protocol Buffers (`ml_inference.proto`).
   * Асинхронная обработка событий, хранение аудиторского следа решений кредитного скоринга.
2. **ML Engine (`src/ml-engine`, Python 3.11 / PyTorch):**
   * Сервис инференса на базе `grpcio` с пулом потоков.
   * Двухбашенная нейронная сеть с механизмом кросс-внимания (`DualTowerCrossAttentionNet`).
   * Математический оптимизатор реструктуризации на базе `ortools.linear_solver.pywraplp` (солвер SCIP).
3. **Ingestion & Feature Store (`src/ingestion`, Redis):**
   * Скользящие окна агрегации (7d, 30d, 90d) транзакций и телеметрии.
   * Вычисление динамических коэффициентов нагрузки и энтропии денежных поступлений.
4. **Agent World & Simulation Engine (`src/agent-world`):**
   * Автономный симулятор кредитной экосистемы: 10 цифровых агентов с индивидуальными поведенческими профилями и реакциями на макроэкономические и личные шоки.
5. **Фронтенд (`src/web`, Next.js 15 / TypeScript):**
   * Интерактивный дашборд риск-офицера с отображением тепловой карты портфеля.
   * Модуль XAI Clean Explainer: визуализация весов внимания для каждого заемщика.
   * Симулятор стресс-тестирования «Что если» и клиентский портал для акцепта реструктуризации.

### 2. Спецификация нейросетевой модели (Dual-Tower Cross-Attention)
#### 2.1. Токенизация числовых признаков (Feature Tokenizer)
В отличие от стандартных полносвязных слоев (MLP), каждый числовой признак $x_i$ проецируется в векторное подпространство размерности $d = 32$:
$$e_i = x_i \cdot W_i + b_i, \quad W_i \in \mathbb{R}^{1 \times d}, \quad b_i \in \mathbb{R}^d$$
Это обеспечивает сохранение индивидуальной семантики каждого финансового и психологического индикатора.

#### 2.2. Механизм кросс-внимания (Cross-Attention)
* Входная финансовая матрица: $X_{fin} \in \mathbb{R}^{B \times 7 \times 32}$.
* Входная психометрическая матрица: $X_{psycho} \in \mathbb{R}^{B \times 9 \times 32}$.
* Линейные проекции:
  $$Q = X_{fin} W_Q, \quad K = X_{psycho} W_K, \quad V = X_{psycho} W_V$$
* Кросс-внимание с 4 параллельными головами (Multi-Head Attention):
  $$\text{Attention}(Q, K, V) = \text{Softmax}\left(\frac{Q K^T}{\sqrt{d_k}}\right) V$$
Результирующая матрица внимания $A \in \mathbb{R}^{B \times 7 \times 9}$ отражает количественную степень влияния каждого психологического симптома на каждый финансовый показатель.

#### 2.3. Multi-Task Learning (MTL)
Сеть решает две задачи одновременно с комбинированной функцией потерь:
$$\mathcal{L} = \mathcal{L}_{BCE}(P_{def}, y) + \lambda \cdot \mathcal{L}_{Huber}(\text{Days}_{pred}, \text{Days}_{true}), \quad \lambda = 0.02$$
где Huber Loss устойчив к выбросам в прогнозе срока наступления кассового разрыва.

### 3. Математическая постановка оптимизации реструктуризации (MILP)
Оптимизатор решает задачу дискретного смешанно-целочисленного линейного программирования:
$$\max_{x_{t,g}} \text{NPV}_{expected} = \sum_{t \in T} \sum_{g \in G} x_{t,g} \cdot \left[ \sum_{m=1}^{t+g} \frac{CF_m(t,g)}{(1 + r)^m} \cdot (1 - P_{def}(t,g)) - \text{LGD} \cdot P_{def}(t,g) \cdot \text{Balance} \right]$$

При ограничениях:
$$\sum_{t \in T} \sum_{g \in G} x_{t,g} = 1, \quad x_{t,g} \in \{0, 1\}$$
$$\text{Payment}_{new}(t,g) \le \min\left( \text{Income} \cdot \text{KDN}_{limit}, \; \text{FreeCashflow} \right), \quad \text{где } \text{KDN}_{limit} = 0.50 \text{ (норматив АРРФР)}$$
$$t \le \text{Tenor}_{original} + 24 \text{ мес.}$$

Алгоритм гарантирует, что предложенный план реструктуризации обеспечивает максимальный возврат средств для банка при выполнении требований регулятора и реальной платежеспособности заемщика.

### 4. Экспериментальные метрики и валидация
Эксперименты проводились на выборке из 25 000 заемщиков с симулированными жизненными траекториями:
* **Train / Val / Test:** 70% / 15% / 15% (стратифицированная выборка).
* **Метрика классификации:** Тестовый **ROC-AUC = 0.941**.
* **Метрика регрессии срока дефолта:** Средняя абсолютная ошибка **MAE = 4.2 дня**.
* **Время работы MILP солвера (SCIP):** 8 – 14.8 мс на решение задачи.
* **Сквозная задержка API (gRPC):** < 25 мс.
